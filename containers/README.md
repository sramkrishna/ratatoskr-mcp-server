# Llamafile Container for Image Analysis

This directory contains the containerized setup for running local vision-capable LLMs using llamafile.

## Overview

The Ratatoskr MCP server uses llamafile running in a Podman container to provide privacy-preserving, local image analysis. Descriptions generated by the vision model are written to image EXIF/XMP metadata, making them searchable through GNOME's LocalSearch and TinySPARQL.

## Quick Start

### 1. Build the Container

```bash
./scripts/build-llamafile-container.sh
```

This creates a container image with llamafile installed and ready to use.

### 2. Download a Vision Model

```bash
./scripts/download-vision-model.sh
```

By default, this downloads LLaVA 1.5 7B (~4GB), which provides a good balance of quality and performance.

**Available models:**
- `llava-1.5-7b-q4` - Recommended for most users (~4GB)
- `llava-1.6-34b-q4` - Better quality, requires more resources (~19GB)

Models are stored in `~/.local/share/ratatoskr-mcp-server/models/`

### 3. Use via MCP Tools

Once set up, you can analyze images through the MCP interface:

```python
# Via Hugin or other MCP client
analyze_image("/path/to/image.jpg")
```

## Architecture

**Container Image:**
- Base: Fedora 40
- Runtime: llamafile (Mozilla AI)
- Vision Model: LLaVA (mounted as volume)

**Workflow:**
1. User requests image analysis via MCP tool
2. Python wrapper runs Podman container with image mounted
3. Llamafile + vision model generates description
4. Description written to image EXIF/XMP metadata via exiftool
5. LocalSearch indexes the new metadata
6. Image becomes searchable via TinySPARQL queries

## Privacy & Performance

✅ **100% Local** - All processing happens on your machine
✅ **No API Calls** - No data sent to cloud services
✅ **No Cost** - Free to use, no API limits
✅ **Searchable** - Descriptions integrated with GNOME search
✅ **Persistent** - Metadata stays with image files

## Container Details

**Image:** `localhost/ratatoskr-llamafile:latest`

**Runtime command example:**
```bash
podman run --rm \
  -v "$HOME/.local/share/ratatoskr-mcp-server/models:/models:ro" \
  -v "/path/to/image.jpg:/tmp/image.jpg:ro" \
  localhost/ratatoskr-llamafile:latest \
  -m /models/llava-v1.5-7b-q4.llamafile \
  --image /tmp/image.jpg \
  --temp 0 \
  -ngl 35 \
  -p "Describe this image in detail for accessibility and search purposes."
```

## Updating

**Update the container:**
```bash
./scripts/build-llamafile-container.sh
```

**Update the model:**
```bash
./scripts/download-vision-model.sh [model-name]
```

## Troubleshooting

**Container build fails:**
- Ensure Podman is installed: `podman --version`
- Check internet connection for downloading llamafile

**Model download slow:**
- Models are large files (4-19GB)
- Download happens only once
- Models can be reused across rebuilds

**Image analysis slow:**
- First run initializes the model (takes longer)
- Subsequent runs are faster
- Consider using GPU acceleration if available

## GPU Acceleration (Optional)

If you have an NVIDIA GPU, you can enable acceleration:

```bash
podman run --rm \
  --device nvidia.com/gpu=all \
  ...
```
